# v2.0 项目结构

更新日期：2026-11-15。

## 目录与职责

```text
gina_sephora/
├── main.py                   应用外壳、左侧导航、桌面退出
├── app_pages/                正式页面入口，不复制业务逻辑
│   ├── new_stock.py          新货页
│   └── existing_stock.py     现货页
├── ui/                       两页共用的界面与会话状态
│   ├── allocation_page.py    规则、选项、上传、检查、计算流程
│   ├── existing_stock_controls.py 现货原生比例编辑表格及门店明细查看
│   ├── formatting.py         页面数字列统一格式，不修改计算值
│   ├── results.py            分货结果展示和下载
│   ├── rules.py              页面规则文案
│   └── state.py              按页面隔离的文件、检查和结果
├── workflows.py              分货模式配置、业务计算入口
├── existing_stock.py         现货需求计划、精确比例、整数分配与 CDC 出库
├── validation.py             文件读取与新货/现货模式校验
├── allocation.py             原有 SOB、整数目标及 CDC 优化
├── adjustments.py            DM 需求计算、库存内结果字段及库存比例预留
├── exporting.py              原有 Excel 生成
├── launcher.py               Windows 单文件桌面启动入口
├── desktop_runtime.py        桌面生命周期
├── auto_update.py            下载校验、子进程检查、本机版本切换与回退
├── release_layout.py         固定运行环境与更新包格式约束
├── version.py                业务代码版本，发布前提高三段版本号
├── update-config.json        固定 GitHub 更新仓库（不包含凭据）
├── packaging/                打包配置、单文件验收脚本
├── tests/                    分页、状态、现货业务及新货回归，内存样例在 fixtures.py
├── docs/                     规则、结构、变更、验收记录
├── README.md                 使用及开发入口
├── build.ps1                 构建命令
├── publish-update.ps1        生成业务代码包，可选自动发布到 GitHub
├── requirements*.txt         应用与构建依赖
├── build/                    构建中间文件，不交付用户
└── dist/                     已构建的 Windows 发布包
```

原有样例及结果文件保留原位置。程序只读取用户手动上传的数据，不会扫描或自动导入项目文件。

## 页面和业务关系

`main.py → app_pages → ui/allocation_page.py → validation.py → workflows.py`

- 新货：`workflows.py → allocation.py → adjustments.py`，常规保留 SOB 规则，DM 先预留并通过共享 CDC 优化保障最低出库。
- 现货：`validation.py(existing_stock=True) → existing_stock.prepare_existing_stock → ui/existing_stock_controls.py → workflows.py → existing_stock.calculate_existing_allocation → allocation.dispatch_warehouses`。
- 两种结果均由 `ui/results.py → exporting.py` 展示和导出；现货不调用 `apply_dm_adjustment`。

新货 DM 需求由 `adjustments.dm_requirements` 提供；`allocation.py` 扣除 DM 需求计算常规目标，再通过 `dispatch_warehouses(minimums=...)` 联合出库。`apply_dm_adjustment` 只补充元数据和兼容列，不再增加出库量。

现货公式、精确比例和取整写在独立的 `existing_stock.py` 中，UI 只负责展示、输入和流程控制。后续变更现货口径时不修改新货默认规则。

## 状态约定

- 新货使用 `new_stock_` 前缀，现货使用 `existing_stock_` 前缀。两个页面的文件、检查、结果、下载均隔离；新货 benchmark/DM 和现货各 item 手动比例也分别保留。
- checkbox 使用 Streamlit 的会话保留机制；上传文件按页面保存文件名及字节，避免上传控件离开页面后被清理导致数据丢失。
- 切换回来时以“当前使用：文件名（已为本页保留）”确认当前数据。即使原生上传框重新显示空白，也继续使用此处列出的文件；重新上传替换，清除按钮删除本页两份文件。
- 文件上传、更换、移除、清除，或 benchmark、DM 变更时，清除本页旧检查、旧分货、旧 Excel，必须重新检查。
- 现货比例变更只清除出库结果和 Excel，保留检查、需求计划及其他 item 的比例；文件变更清除本页需求计划和全部比例。
- 现货原生编辑表格只开放最后一列手动比例。使用固定输入快照承接连续编辑，避免将编辑结果直接覆盖原表而导致隔次输入丢失；非法比例修正后重新挂载展示正确值。页面切换后从已确认的各 item 设置恢复表格。
- 门店明细通过表格下方统一折叠区选择 item 查看；关闭时不构建门店明细视图。表格与需求计划按输入版本隔离。
- 页面切换和普通重跑不会重新计算，已生成的 Excel 在本页会话中复用。
- 以上保留只针对同一浏览器会话；关闭会话或重启服务后需要重新上传，不将业务文件写入磁盘。

## 文件整理约定

- 新页面放 `app_pages/`；共用界面放 `ui/`；业务计算保持独立于 Streamlit。
- 规则变更集中更新 [分货规则.md](分货规则.md)，结构变更更新本文件，完成的改动记录到 [变更记录.md](变更记录.md)。
- 业务样例或用户结果不混入源码目录的新子模块，不为本次结构改造移动或重命名原始文件。
- `.venv/`、`__pycache__/`、`build/`、`dist/`、日志作为环境或产物，不作为业务源码维护。
- `dist/GinaSephora-v1.0.exe` 是历史发布包，没有更新器。新版入口为 `dist/GinaSephora.exe`，启动时选择内置或已验证的新版业务代码；更新流程和运行环境边界见 [自动更新.md](自动更新.md)。
