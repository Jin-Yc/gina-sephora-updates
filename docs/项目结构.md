# 项目结构与维护约定

更新日期：2026-11-15。主要源码统一放在 `gina_sephora/` 应用包中。

## 目录与职责

```text
gina_sephora/
├── main.py                        Streamlit 应用外壳和导航
├── launcher.py                    桌面启动入口，兼容现有 exe
├── version.py                     业务版本号
├── auto_update.py                 固定更新器：下载、校验、切换与回退
├── desktop_runtime.py             固定桌面生命周期和退出控制
├── release_layout.py              固定更新协议和路径约束
├── update-config.json             GitHub 更新源配置，无凭据
├── gina_sephora/                   应用源码包
│   ├── domain/                    分货和补货业务规则
│   │   ├── allocation.py          SOB 目标、整数补齐、CDC 优化
│   │   ├── adjustments.py         DM 需求与库存限制
│   │   └── existing_stock.py      现货需求、比例与补货计算
│   ├── data_io/                   输入与输出
│   │   ├── validation.py          Excel/文本读取和业务校验
│   │   └── exporting.py           Excel 结果生成
│   ├── services/
│   │   └── workflows.py           两种分货模式的流程入口
│   ├── app_pages/                 Streamlit 页面入口
│   │   ├── new_stock.py
│   │   └── existing_stock.py
│   └── ui/                        共用界面与会话状态
│       ├── allocation_page.py     文件上传、检查和计算流程
│       ├── existing_stock_controls.py 现货比例编辑和门店明细
│       ├── formatting.py          数字格式
│       ├── results.py             结果和下载
│       ├── rules.py               规则文案
│       └── state.py               分页状态管理
├── packaging/                     PyInstaller 配置、更新包生成、exe 验收
├── tests/                         业务、页面和自动更新回归，fixtures 为内存样例
├── docs/                          结构、规则、发布、Git 管理和验收说明

│   └── logs/                      构建和验收日志
```

根目录保留启动、版本和固定更新协议文件，是为了维持现有 exe 的启动约定。普通业务和界面修改集中在应用包中。业务 Excel 保留原位置并由 Git 忽略；程序只读取用户手动上传的数据。

## 依赖与导入

源码统一使用完整包名，例如：

```python
from gina_sephora.domain.allocation import calculate_allocation
from gina_sephora.data_io.validation import validate_uploads
from gina_sephora.services.workflows import NEW_STOCK
from gina_sephora.ui.allocation_page import render_allocation_page
```

页面保持直接执行的短脚本，将共用渲染交给 `ui`，将业务流程交给 `services`。业务规则保持独立于 Streamlit。

调用关系为 `main.py → gina_sephora/app_pages → ui → data_io / services → domain`。新货由 `domain/allocation.py` 和 `domain/adjustments.py` 处理，现货由 `domain/existing_stock.py` 处理，均复用 CDC 出库优化；结果由 `data_io/exporting.py` 导出。

## 发布与旧 exe 兼容

`packaging/release_tools.py` 将开发目录转换为现有 2.1 更新器接受的交付目录：业务模块生成原根目录路径，界面生成 `ui/`，页面生成 `app_pages/`，并转换对应包导入。启动入口的业务导入也在构建时转换。

因此源码可以按包管理，现有 exe 仍可安装后续业务更新包。更新器本体和实际启动逻辑没有改变，运行环境指纹与现有 exe 保持一致。目录映射是发布边界的一部分，不能直接压缩整个开发目录充当更新包。

`domain/`、`data_io/`、`services/` 中的模块名应唯一；新增子包、跨目录同名模块、动态导入或包初始化逻辑时，需要同步检查发布映射。`__init__.py` 保持为包声明，共用功能放入明确的模块。转换后有重复路径或遗漏必要模块会拒绝生成更新包。

PyInstaller 分析应用包以收集第三方依赖，将业务模块以可更新源码方式交付。`build/` 中的转换源码和启动入口属于生成文件，不在这里手动维护。

`packaging/runtime_certificates.py` 是 exe 的证书启动钩子，在更新器启动前指定内置公共 CA 文件；仅在用户未显式配置 CA 文件时生效。它不进入业务更新包，修改后需要重建和交付 exe。证书数据与初始化方式不改变现有业务模块的兼容协议；详细限制见 [自动更新.md](自动更新.md)。

## 状态约定

- 新货使用 `new_stock_` 前缀，现货使用 `existing_stock_` 前缀。两个页面的文件、检查、结果、下载均隔离；新货 benchmark/DM 和现货各 item 手动比例也分别保留。
- checkbox 使用 Streamlit 的会话保留机制；上传文件按页面保存文件名及字节，避免上传控件离开页面后被清理导致数据丢失。
- 切换回来时以“当前使用：文件名（已为本页保留）”确认当前数据。即使原生上传框重新显示空白，也继续使用此处列出的文件；重新上传替换，清除按钮删除本页两份文件。
- 文件上传、更换、移除、清除，或 benchmark、DM 变更时，清除本页旧检查、旧分货、旧 Excel，必须重新检查。
- 现货比例变更只清除出库结果和 Excel，保留检查、需求计划及其他 item 的比例；文件变更清除本页需求计划和全部比例。
- 现货原生编辑表格只开放最后一列手动比例。使用固定输入快照承接连续编辑，避免将编辑结果直接覆盖原表而导致隔次输入丢失；非法比例修正后重新挂载展示正确值。页面切换后从已确认的各 item 设置恢复表格。
- 门店明细通过表格下方统一折叠区选择 item 查看；关闭时不构建门店明细视图。表格与需求计划按输入版本隔离。
- 页面切换和普通重跑不会重新计算，已生成的 Excel 在本页会话中复用。
- 以上保留只针对同一浏览器会话；关闭会话或重启服务后需要重新上传，不将业务文件写入磁盘。

## 文件整理约定

- 新页面放 `gina_sephora/app_pages/`；共用界面放 `gina_sephora/ui/`；分货规则放 `domain/`，数据读写放 `data_io/`，业务流程放 `services/`。
- 调整业务规则时更新 [分货规则.md](分货规则.md)，调整结构时更新本文件，完成的工作记录到 [变更记录.md](变更记录.md)。
- 原始业务样例和结果文件不放入 Python 包，不纳入 Git；它们的现有路径保留。
- `.venv/`、缓存、日志、`build/`、`dist/` 作为开发环境或生成产物，由 Git 忽略。
- 现有交付入口仍为 `dist/GinaSephora.exe`；本次目录整理不会覆盖这个文件或已发布 Release。新布局验收产物放在 `build/refactor-dist/`。
- Git 同步见 [Git管理.md](Git管理.md)，程序更新发布见 [自动更新.md](自动更新.md)。
