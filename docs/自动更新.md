# 桌面程序自动更新

用户始终双击同一个 `GinaSephora.exe`。程序在打开分货页面前检查 GitHub Releases，发现兼容的新版业务代码后自动下载、校验、安装并运行新版。用户不需要访问 GitHub、下载 ZIP 或替换 exe。

源码及更新仓库：https://github.com/Jin-Yc/gina-sephora-updates 。`main` 分支管理源码、测试和文档，Releases 提供程序更新；不上传业务 Excel、用户输入、凭据和开发环境。日常同步见 [Git管理.md](Git管理.md)。

首个正式发布版本为 [2.1.1](https://github.com/Jin-Yc/gina-sephora-updates/releases/tag/v2.1.1)。已验证内置 2.1.0 的同一 exe 从 GitHub 自动更新至 2.1.1，并能在下次启动时直接复用本机新版。交付 exe 无需重新构建。

## 2.1.2 业务更新

本版在新货和现货的结果文件中增加“CDC 库存合计”。更新包与既有 2.1 exe 的运行环境兼容，用户继续使用同一 exe。

程序已运行时请先点击网页“退出程序”，再双击启动；重复双击正在运行的程序只会打开已有实例，不触发升级。业务原始 Excel 和既有导出文件不会被更新包上传或覆盖。

## 首次交付

### 2026-11-27 · 桌面证书加载修复

若日志包含 `CERTIFICATE_VERIFY_FAILED`，说明 HTTPS 证书校验未通过；需同时查看后面的详细原因，缺少签发机构、证书过期和公司网络证书应分别排查。

桌面修复版通过 PyInstaller 启动钩子，在未显式配置 `SSL_CERT_FILE` 时将其指向 exe 自带的 certifi 公共 CA 文件。Python 仍加载 Windows 的 CA/ROOT 信任库；已经配置的公司 CA 文件保持原值。始终验证证书链和主机名，不关闭证书校验，也不修改电脑的系统证书。

修复仅涉及打包时的证书初始化，业务仍为 2.1.2，固定更新器、Python 和业务依赖未变；运行环境指纹及原业务更新包保持兼容。缺失公共 CA 时，此修复可消除对开发电脑 Conda 证书路径的依赖；企业代理证书不受信任、系统日期错误或证书过期仍需根据完整日志处理。

证书修复位于 exe 中，已无法联网更新的旧 exe 需要手动替换一次。桌面附件单独发布，不替换既有业务 ZIP、清单和 Latest 业务 Release。后续业务代码仍按原流程自动更新。

交付地址：[桌面证书修复版（内置业务 2.1.2）](https://github.com/Jin-Yc/gina-sephora-updates/releases/tag/v2.1.2-desktop.1)。退出正在运行的旧程序后，下载附件 `GinaSephora.exe` 替换旧 exe 再启动；仅重命名旧 exe 不会应用此修复。

构建入口：`packaging/runtime_certificates.py`、`packaging/GinaSephora.spec`；构建依赖锁定 certifi 版本。不要把证书启动钩子作为普通业务更新包发布。

技术依据：[Python 3.13 系统证书加载](https://docs.python.org/3.13/library/ssl.html#ssl.SSLContext.load_default_certs)、[PyInstaller 运行时钩子](https://pyinstaller.org/en/stable/when-things-go-wrong.html#changing-runtime-behavior)。

把 `dist/GinaSephora.exe` 发给用户一次。历史 v1.0 exe 没有更新器，必须首次更换。新版 exe 内置完整 Python、依赖和业务代码，即使未联网也可以首次使用。

用户电脑需要能通过 HTTPS 访问 GitHub 及其 Release 下载服务。检查/下载失败会在侧栏显示状态并继续运行本机版本，不会清空用户上传的业务文件。程序已经运行时再次双击只打开已有页面；需要先点击“退出程序”，下次启动才检查更新。

## 日常修改和发布（维护者操作）

1. 修改业务代码或页面，完成测试。
2. 在 `version.py` 中提高 `APP_VERSION`，例如从 `2.1.1` 改为 `2.1.2`，使用三段数字，不能重复使用已发布版本号。
3. 生成小型代码更新包，无需运行 PyInstaller：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\publish-update.ps1
   ```

4. 在仓库的 Releases 页面创建相同版本的正式 Release（例如 tag `v2.1.2`），把输出目录中的 `update.json` 和 `GinaSephora-app-2.1.2.zip` 一起上传，两个附件完整后再发布并设为 Latest。不要选择预发布。
5. 用户下次双击现有 exe 时自动更新；不需要再次给用户发文件。

也可以登录 GitHub CLI 后一条命令完成生成、上传和发布：

```powershell
gh auth login
powershell -ExecutionPolicy Bypass -File .\publish-update.ps1 -Publish
```

`-Publish` 先创建包含两个附件的草稿，再发布为 Latest，避免用户下载到只上传一半的版本。已存在的 Release 不覆盖，失败的草稿请检查附件后再发布。GitHub CLI 的维护者登录只保存在开发电脑，不会打包到用户 exe。

GitHub 的固定 Latest 附件地址形式见 [官方说明](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)。更新器使用 `releases/latest/download/update.json` 查询，清单中的 ZIP 地址固定到具体 tag，避免更新过程混用两个版本。

## 哪些内容可以自动更新

- `gina_sephora/domain/`、`data_io/`、`services/` 中的业务模块，以及 `gina_sephora/ui/`、`gina_sephora/app_pages/` 中的界面与页面。
- 页面、文案、分货规则、校验和 Excel 导出逻辑。
- 每个更新包包含完整业务代码快照，用户可以跨多个版本直接更新。

以下内容属于固定运行环境，变更后需要重新构建、验证并交付新版 exe：

- Python、`requirements.txt` 中的第三方库及其版本。
- `launcher.py`、`desktop_runtime.py`、`auto_update.py`、`release_layout.py` 的实际运行逻辑。仅源码包导入路径调整会在发布时转换为原有入口，不改变运行环境指纹。
- 更新仓库地址和 PyInstaller 打包配置。
- 新增的图片、非 Python 资源，以及新增第三方依赖。

运行环境指纹会随 Python 主/次版本、依赖清单和固定启动器代码变化。不兼容时拒绝安装代码更新，侧栏提示需要新版 exe。仅新增第三方 import 而没有把依赖打进旧 exe，也可能不能运行；可复用模块中的缺失依赖会在子进程检查阶段被拒绝。

开发目录与交付目录分开：发布脚本自动把业务包目录和包导入转换为 2.1 启动器支持的原有路径，同时转换页面路径。开发时统一从 `gina_sephora` 包导入；不要手动把模块拷回根目录，也不要在 `build/` 中维护源码。新增业务子包、同名模块或特殊动态导入时，需要同步检查 `packaging/release_tools.py` 的映射和兼容性测试。

## 校验、存储和恢复

- 使用 HTTPS 并验证证书，拒绝降级到 HTTP 的重定向；ZIP 必须来自配置仓库的 Release。
- 下载校验 SHA256，逐个校验源码散列、语法和必需文件；限制包大小，拒绝越界路径、重复路径、符号链接和启动器覆盖。
- 在独立子进程导入可复用模块，检查失败继续旧版。页面脚本只作语法检查，此检查不能替代发布前的业务和页面测试。
- 下载在独立临时目录完成，检查通过后才原子切换本机版本指针；下载中断不影响原版本。
- 更新缓存位于 `%LOCALAPPDATA%\GinaSephora\updates`，按仓库和运行环境隔离，无需管理员权限，exe 所在目录可以只读。
- 原版本保留；缓存源码损坏时尝试上一版，再回到 exe 的内置版本。
- 更新包公开可下载，业务 Python 源码也因此可见；HTTPS 和散列校验不能抵御发布账号被接管，维护者需要妥善保护 GitHub 账号。

如果发布后发现业务问题，先在网页点击“退出程序”，然后在 exe 所在文件夹执行：

```powershell
.\GinaSephora.exe --rollback
```

程序回到上一版（第一次更新的上一版为内置版本），并记住跳过这个更新包；后续更高版本仍会正常更新。仅临时跳过本次联网检查可执行：

```powershell
.\GinaSephora.exe --skip-update
```

回退不会恢复上次浏览器会话中的上传和计算结果，重启后仍需重新上传业务输入。

## 开发与验证

源码直接运行 Streamlit 不启用桌面更新器，不会用远端代码覆盖开发目录。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
powershell -ExecutionPolicy Bypass -File .\build.ps1
.\.venv\Scripts\python.exe packaging\verify_release.py
.\.venv\Scripts\python.exe packaging\verify_update_release.py --expected-version 2.1.1
```

`tests/test_auto_update.py` 覆盖真实代码包安装、子进程依赖检查、离线复用、坏包拒绝、运行环境不兼容、回退跳过、缓存损坏恢复和 ZIP 路径限制。`verify_release.py` 验证单独复制 exe、清空 Python/Conda 搜索路径后的业务计算、Excel 导出、两个页面和退出功能。

`verify_update_release.py` 在独立临时缓存中验证实际 GitHub 联网升级和跳过联网检查后的新版复用，不影响用户已经安装的版本。`--expected-version` 应填写当前 Latest Release 的业务版本。
